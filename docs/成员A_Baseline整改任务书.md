## 3. 原始 BP Baseline：固定并验证

### 3.1 当前 B0 配置

当前原始 BP 结构：

``` text
TF-IDF 输入
    ↓
Linear(input_dim, 256)
    ↓
ReLU
    ↓

    ↓

    ↓

```

当前参数：

  项目                                         值
  ------------------------- ---------------------

  隐藏层神经元                                256
  隐藏层数                                      1
  激活函数                                   ReLU
  Dropout                                     0.2
  输出类别数                                    6
  优化器                                     Adam

  Weight Decay                             0.0001
  Batch Size                                   64

### 3.3 修复训练与验证损失的统计口径

历史 `train_loss` 是训练模式下的在线损失，来自不同
batch、不同参数更新状态，并且 Dropout 处于开启状态。

它不能直接与 epoch 结束时的验证损失进行严格同口径比较。

要求：

1.  保留历史 `train_loss`，不要覆盖或伪造历史数据。
2.  将新记录明确命名为 `train_online_loss`。
3.  每轮全部参数更新结束后，切换至 `eval()`。
4.  使用 `torch.no_grad()`，在完整训练集上分 batch 计算
    `train_eval_loss`。
5.  使用同一模型状态、同一评估模式和同一 CrossEntropyLoss 计算
    `val_loss`。
6.  两种 loss 均按样本数加权。
7.  评估过程不得更新参数、产生梯度或消耗 Dropout 随机数。
8.  历史实验没有记录的 `train_eval_loss` 不得补造。

当前 Member A
审计目录已经包含这项新增记录和相应测试。实施前应先核对仓库当前代码，避免重复修改。

## 4. Baseline 训练问题：用证据确认过拟合

### 4.1 已发现的现象

-   Macro-F1 最佳 epoch 为 3。
-   验证 Loss 最低点在 epoch 4。
-   训练在线 Loss 持续下降。
-   验证 Loss 在早期下降后持续上升。
-   Early Stopping 最终在 epoch 13 停止，并恢复最佳 Macro-F1
    checkpoint。

Member A 的补充审计还计算了同一 epoch 结束状态下的训练集评估 Loss：

  Epoch     Train Eval Loss   Validation Loss
  ------- ----------------- -----------------
  1                1.117927          1.255759
  3                0.224267          0.687028
  4                0.135115          0.681630
  13               0.024436          0.814027

这支持后期过拟合的判断。

### 5.2 重点类别

当前原始 BP 的验证集结果显示，社会类别是主要困难类别：

  类别     Validation F1
  ------ ---------------
  财经            0.7047
  体育            0.8807
  文娱            0.7322
  教育            0.7929
  社会            0.5755
  国际            0.8872

优先分析：

-   社会 → 财经
-   社会 → 文娱
-   财经 → 社会
-   文娱 → 社会
-   教育 → 社会

### 5.3 错误样本归因规则

对验证集错分样本进行人工检查，并使用以下类别标记：

  --------------------------------------------------------------------------------------------------
  错误类型                            判断依据
  ----------------------------------- --------------------------------------------------------------
  频道语义交叉                        新闻内容可能同时符合两个频道的编辑分类

  标题信息不足                        标题过短、抽象、缺少主体或背景

  分词/特征表达问题                   标题包含数字、专名、未登录词或组合表达，当前特征表示可能不足

  疑似标签噪声                        标题与频道标签明显不一致，但必须进一步核查原始资料

  暂无法判断                          证据不足，不强行归因
  --------------------------------------------------------------------------------------------------

要求：

1.  主要错误分析使用 Validation 数据。
2.  典型案例必须保留 ID、标题、真实标签和预测标签。
3.  不只挑选支持既定观点的错误样本。
4.  人工归因必须说明判断依据。
5.  不得把"模型可能没有学好"写成已经证实的原因。
6.  不得用测试集错误案例反复调整模型。

### 5.4 特征表达诊断

在不改变 B0 的前提下，检查：

-   [ ] jieba 分词后的平均 token 数。
-   [ ] 空 token 文档比例。
-   [ ] 训练集词表规模。
-   [ ] 验证集未登录词比例或覆盖率。
-   [ ] 纯数字过滤造成的信息损失案例。
-   [ ] 专有名词、机构名称、赛事名称的分词情况。
-   [ ] 典型错分标题的分词结果和 TF-IDF 非零特征。
