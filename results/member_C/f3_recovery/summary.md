# F.3 原始训练数据恢复与可行性审查

## 结论

2025 年 365 个归档日均成功采集。原始记录 **165,125** 条，使用项目现有清洗规则、无每类配额截断后得到 **97,798** 条。与既有划分进行精确及高相似筛查，并保守剔除候选内部高相似对两侧后，保留 **90,742 条待人工复核的新增候选**。

候选类别极不均衡，教育类只有 371 条。若保留全部 6,549 条原训练样本并按现有六类比例扩充，**不支持约 2 倍或 4 倍**：2 倍至少需要新增 1,064 条教育新闻，4 倍需新增 3,192 条。按教育类数量估算的比例保持上限约为 **1.349 倍**；这只是数量上限，不保证人工核实或更严格的语义去重后仍可达到。

建议审核后优先考虑约 **1.30 倍、8,512 条**的初步规模实验，而非把所有候选直接加入。按基准六类比例分别向下取整，并保持原训练样本：

| 类别 | 基准 | 可新增候选 | 建议新增 | 建议总数 |
|---|---:|---:|---:|---:|
| 财经 | 1,109 | 32,240 | 332 | 1,441 |
| 体育 | 1,107 | 5,572 | 332 | 1,439 |
| 文娱 | 1,134 | 6,290 | 340 | 1,474 |
| 教育 | 1,064 | 371 | 319 | 1,383 |
| 社会 | 1,057 | 31,758 | 317 | 1,374 |
| 国际 | 1,078 | 14,511 | 323 | 1,401 |
| 合计 | 6,549 | 90,742 | 1,963 | 8,512 |

这只是实验设计，**未生成训练集，也未启动训练**。后续应先人工审核冲突，再在各类内按月或时间分层、固定数据抽样种子构造逐级包含的子集；每个规模独立在其训练子集上拟合词表、IDF 和卡方筛选器。教育类建议新增量已占该类候选的约 86%，需先核实可用性。候选涉及验证/测试标题的检查仅用于隔离重复，不用其标签和模型表现选择数据。

## 恢复方式与隔离

`main.py` 的 `--outdir` 只更改数据目录，不能隔离 `state/checkpoint.json`、`state/raw_parts/` 或默认日志。因此新增本目录中的 `recover_2025.py`：复用原有 `main.cmd_crawl`、`main.cmd_clean`、解析和清洗代码，在进程内将数据、断点、切片、报告和日志路径全部设为本目录下的独立位置；采集完成后以 `max_per_class=0` 清洗。拒绝覆盖已有数据文件，并对未登记的缓存切片拒绝续采。

执行命令：

```powershell
$env:PYTHONUTF8='1'
D:\WorkSpace\PATH\Miniconda\envs\math\python.exe results/member_C/f3_recovery/recover_2025.py
```

请求单线程、默认间隔 1.2 秒并附加项目原有的短随机抖动。采集前读取 `robots.txt` 并检查归档路径允许访问；遇到 401、403、429、请求失败、缺失容器、分页或空解析时停止，不绕过限制。实际采集中未触发停止条件。首次验证的 2025-01-01 页面返回 HTTP 200，可解析出 393 条，未检测到分页。采集启动后，入口文件补充了对未登记缓存切片的续采防覆盖检查；该补充不影响已启动进程的采集和清洗逻辑。

主项目的 `dataset/news_clean.csv`、三个划分和版本文件未改动；训练、验证和测试划分的 SHA-256 与版本登记一致。测试集只读取 ID、URL、标题和发布时间用于排重，未读取其标签进行筛选或模型评估。

## 覆盖和清洗

| 检查 | 结果 |
|---|---:|
| 请求 / 成功归档日 | 365 / 365 |
| 404、请求失败或解析失败的归档日 | 0 |
| 发现分页的归档日 | 0 |
| 原始记录 | 165,125 |
| 原始无效时间或归档日不一致 | 0 |
| 清洗后六类记录 | 97,798 |
| 清洗后实际发布时间范围 | 2025-01-01 00:10 至 2025-12-31 23:01 |

原始数据中 ID 重复计数为 11 条（按首次出现后计数，其中包含空 ID），URL 重复 3 条，按现有标题清洗规则计数的重复标题 4,130 条。原项目清洗步骤依次过滤和去重，因此各步骤剔除数不应与全原始表中的独立重复计数相加；实际统计见 `data/crawl_report.json`。清洗结果中原始 ID、URL、标题各无精确重复；采用额外 NFKC/去标点等规范化后，标题仍有 36 条额外重复记录，并已在候选间相似筛查中处理。

清洗后的六类数量：财经 33,547、体育 6,721、文娱 7,441、教育 1,438、社会 32,939、国际 15,712。类别沿用原始栏目映射，特别是“文化→文娱”；没有根据标题改标签。每月清洗记录在 6,938 至 9,139 条之间，12 个月均有记录，未发现整月缺失。教育类候选各月均有但差异明显，例如 1 月 16 条、9 月 53 条。

归档页仅提供月、日、时、分，年份由归档页面路径补齐；本次未逐篇核对文章页发布时间，不能将时间格式一致等同于独立证明实际发布时间真实无误。

## 重复、标签冲突和泄漏风险

- 原训练集 6,549 个 ID 全部出现在恢复后的清洗数据中，同 ID 记录的标题、URL、时间和类别未发现变化。恢复数据与原训练集按任一 ID、规范化 URL 或规范化标题匹配 6,555 条，其中 6 条为额外的标题规范化冲突；与验证集、测试集的这些精确匹配均为 0。
- 恢复数据与原训练集存在 1 组规范化标题相同但类别不同的冲突，保存在 `analysis/train_label_conflicts.csv`，没有修改原训练标签。原始目标栏目记录中还有 54 组清洗标题跨目标类别的情况，供审查，见 `analysis/raw_title_label_conflicts.csv`；这些组不自动说明标签错误。
- 近重复沿用上一阶段规则：标题经 NFKC、大小写折叠、仅保留字母数字后，以字符三元组集合 Jaccard ≥ 0.80 判定。排除精确匹配后，新增候选分别有 31、1、3 条与训练、验证、测试集存在高相似关系，已从候选清单剔除；逐条对应关系见 `analysis/near_reference_conflicts.csv`，原训练样本保持不变。
- 剩余候选内部检出 244 对、涉及 466 条高相似记录。为了提供保守的候选数，清单将每对两侧均排除；清单和 `analysis/near_candidate_conflicts.csv` 均保留证据，供人工判断。高相似标题未必是同一事件；反过来，三元组阈值也不能排除改写或同事件不同标题的语义泄漏。
- 原训练集自身此前检出 4 对、涉及 5 条高相似标题。既要全部保留基准又要严格消除其内部近重复，需要人工审核后决定，不能在本次擅自删除。
